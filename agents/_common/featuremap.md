## Feature map
The repo keeps a feature map in `docs/FEATURES.md` (or the file the repo already uses for this).
It lets later agents find and check each feature. Each feature has one entry:
- Name, and what the feature does in one sentence.
- Entry point: the command, route, or UI path.
- Use: numbered steps with exact commands or clicks.
- Check: the command to run and the output to expect.
- Code and tests: the file paths.
Keep entries short. Update the entry when a feature changes. Do not remove entries of other features.
